# 指定人物语音提取：准确性与完整召回联合优化方案

日期：2026-09-24。状态：已实施基线冻结、阶段审计及离线 T0/T1 原型；英语公开语音 T1 训练完成，但日语动漫开发反例未通过，尚无可验证的实际提取增益，未接入正式引擎。阶段证据见 [第一集审计记录](episode1_stage_audit_20260924.md)与[训练数据门禁](training_data_gate_20260924.md)。

设计依据：当前代码提交 `734bd071e5c320e78216292b76fd2c0323aa947d`、仓库内第一集历史试听记录、字幕局部验证记录，以及用户历次反馈。用户随后已要求执行本方案；本文仍是设计依据，不代表各阶段已完成。未经用户明确要求不上传远端。

## 0. 结论与主线

目标不是“让通过的文件变多”，而是从源音频中找回尽可能多的、确实属于参考人物的完整讲话，同时不混入其他人物、歌声或多人重叠。

推荐路线分为两个必须配合的部分：

1. **避免流程提前丢失信息。** 保存连续时间轴、候选及其出处，明确每段目标讲话究竟在哪个阶段丢失；让切分与身份判断可以在原始上下文中复核，但不跨越用户规定的硬边界。
2. **实质提高身份判别能力。** 验证并按需训练一个“参考音频条件下的时序判别器”：同时学习人物归属、其他声音侵入和换人位置。它仍使用声学身份特征，不是摆脱声纹的魔法；重点是改变学习任务与保留的信息，而不是叠加余弦阈值。

这不是直接采购一个 Personal VAD、TS-VAD 或目标分离模型就能完成的方案。先测现有流程上限和模型表征上限，再决定具体训练范围。模型训练不是无条件优于现有模型，必须经过独立验收。

优先级：错误人物/歌声/重叠污染与语音完整性属于发布硬约束；在满足约束的候选中提高完整召回。处理时间不是优先限制，但显存、磁盘、数据授权与可复现性仍需控制。

## 1. 需求、边界与术语

### 1.1 必须保持的产品行为

- 多段目标参考音频；多个待处理音频或视频；参考数量不固定。
- 可选排除人物，每个人物多段参考，独立添加或删除；不提供排除人物也必须工作。
- 目标是参考人物的实际讲话，不是音色相近的人，也不是通过生成模型模拟出来的声音。
- **先处理有人演唱的歌声，再做 UVR。** 纯器乐背景不等于歌声；只有器乐、没有讲话的区间不输出。
- 排除同时讲话、目标讲话与他人歌声同时出现等污染。多人先后讲话不等于重叠，应找出真实换人边界。
- 切分先以讲话/静音边界产生候选，再检查内部换人。不能只靠字幕切，也不能默认一个静音块只有一人。
- 静音下限默认 `0.20 s`、上限默认 `0.85 s`。规则见第 5 节。
- 中文字幕只提供时间提示；不能认定人物身份，也不能翻译回日语后冒充 STT。
- STT 在最终音频边界确定之后；日文原音输出日文转写。
- 输出 UVR 清理后的真实音频及对应文本；保留响度整理、批次统一 ZIP、可选视频片段与保存位置。
- 中文桌面 UI、英文程序名称、已有依赖复用与缓存机制保持。
- 正式使用仍是一键流程，不要求每次人工给候选打标签或重新训练。
- 不针对某一集、某一句、某个时间点写放行或拦截规则。

### 1.2 “不漏、不多加”的可验收定义

定义三个集合：

- **合格目标讲话**：目标人物的讲话，且存在可完整截取的单人、非歌声片段。
- **按需求排除的内容**：歌声、多人重叠、非目标人物、无人讲话区间。
- **真值暂不明确的内容**：人工也无法可靠判断人物或边界的片段。必须单独报告，不能偷偷删除困难样本来提高指标。

召回率的主要分母是“合格目标讲话”，不是全片所有声音。目标人物在重叠中说的话仍按用户规则排除，但必须另外报告这部分时长，不能伪装成从未出现过。

“完整”首先指没有截掉原有语音的声学完整话段，包括清辅音、塞音释放和轻声尾音；不是只保留声带振动明显的部分。字幕中的语法整句可能跨越长停顿，不能据此突破 `0.85 s` 硬切要求。可用同一 `sentence_group_id` 表示相关话段，不擅自合并音频文件。

### 1.3 固定短句下限与完整召回的冲突

当前最终输出仍有 `1.20 s` 下限。它是训练素材长度偏好，不是“是不是目标人物”的证据。

新设计建议将其与身份判断彻底分离：

- 完整且身份明确的短句也属于合格目标讲话。
- 不能拼接不相关语音凑时长，不能通过补零让身份模型误以为证据变多。
- 如保留训练用最短时长设置，应作为显式、可关闭的导出过滤；日志明确记录为“长度策略排除”。
- 默认是否取消现有 `1.20 s` 导出下限属于待确认的产品行为变化，本次不修改默认值。
- 不论用户启用何种长度策略，报告同时给出过滤前召回和过滤后交付量，不能通过改变分母掩盖遗漏。

这些不能作为默认“新突破”。如果要重试，必须先说明具体发生了什么新变化，例如新的任务训练、不同的输入信息或已定位的实现缺陷；明确实验假设与停止条件。

历史口述结果只作为风险线索。无法找到对应版本、输入和报告的实验不编造数字，也不能断言某一算法在所有条件下都无效。

## 3. 第一阶段：建立基准与定位真正的上限

### 3.1 基准冻结

保存现有提交号、模型指纹、参考列表、排除组、字幕绑定和全部参数。比较的是同一源音频、同一参考、同一导出规则下的新旧结果。

源区间使用 `source_hash + start_sample + end_sample` 标识；`0008` 这样的输出编号不是跨运行身份标识。允许合并或拆分造成文件编号改变，不允许因此丢失回归对应关系。

第一集长期参与开发，只能作为开发/回归集。之前参与反馈的其他集也不能重新包装成未知测试集。

### 3.2 完整标注，而不只标输出

研发需要一组完整标注的场景或整集：目标人物全部讲话、非目标讲话、重叠、歌声、讲话边界、身份和边界争议。

- 现有人工确认样本可直接形成回归子集，但不足以计算全片召回率。
- 模型可预标注，最终真值需要人工听辨与核对；模型自身的高分不等于真值。
- 人工可以使用画面协助建立真值，但产品推理不能依赖未提供的视频或人物姓名。
- 边界记录最早/最晚合理位置及争议区，不要求人工伪装成采样点精度。
- “机器不确定”的真实目标句话计为漏检，不能移出分母。
- “人工不确定”单列，并给出乐观/悲观统计范围与待审清单。
- 开发期的标注是必要研发成本；当前没有已经齐全的完整真值集，也没有安排好的独立标注人员。不能承诺纯自动生成可靠真值。

### 3.3 分阶段漏失审计

对每一条合格目标讲话回答：

1. 歌声阶段有没有错误屏蔽？
2. UVR 是否损伤到讲话/身份信息？
3. VAD/静音候选有没有覆盖完整语音，包括首尾清辅音？
4. 重叠检查有没有误判或整段连带拒绝？
5. 换人切分有没有切错、漏切或形成不可识别碎片？
6. 身份模型与排除人物在哪一步拒绝？
7. 后续边界修正、短句下限、STT 有没有再丢失？

同时记录“首次丢失原因”和其他同时存在的障碍。不能只统计首次原因，误以为修复这一处就一定能恢复。

### 3.4 离线理想裁决实验（oracle）

只在带真值的评估器内，用真实标签替换某个阶段的判决，测该阶段完美时现有流程最多能恢复多少完整目标语音。真值不得进入正式推理路径。

至少比较：完整候选上限、完美身份判决上限、完美边界上限、预过滤误杀修复上限。测试单阶段及关键两阶段组合；各阶段相关，收益不能简单相加或相乘。

决策依据：

- 若目标讲话大部分在身份模型之前已不可达，优先改候选/预过滤结构。
- 若候选完整但相似角色与目标人物分不开，进入身份表征训练。
- 若身份正确但边界污染/截音为主，优先训练边界与局部污染检测。

交付：每条遗漏的出处、原因、是否可恢复以及整集上限报告。尚无真值时只报告流程统计，不称为召回率。

## 4. 总体架构与数据契约

```text
原始媒体 + 多参考 + 可选排除人物 + 可选字幕
    ↓
解码并建立唯一源时间轴
    ↓
歌声检测与边缘精修（先完成；保留事件记录）
    ↓
UVR（保留与原音的精确时间对应）
    ↓
静音/VAD 候选 + 可选字幕时间辅助 + 漏候选复核
    ↓
候选及上下文 → 参考条件时序判别器
                ├─ 目标身份活动
                ├─ 其他讲话活动 / 混入风险
                └─ 换人位置 / 边界证据 / 不确定性
    ↓
结合歌声与重叠掩码，形成可独立完整输出的话段
    ↓
边界精修、排除人物复核、片段纯净度与完整性终审
    ↓
冻结最终音频区间 → 响度整理 → STT → 音频/文本/可选视频/批次 ZIP
```

旧引擎在研发阶段作为冻结对照，不作为新引擎每条结果必须同时通过的额外总闸。否则新模型即使恢复真实漏检，也会被旧门再次拦下。

### 4.1 唯一时间轴

- 以解码后的源采样时间和整数样本索引为权威；展示才转浮点秒。
- 各模型可以用自己的采样率，但必须保存重采样、分块、补零、裁切和模型延迟映射。
- 原音/UVR 不默认零延迟；用受控脉冲/语音及真实片段验证延迟，无法对齐时不进行跨通道边界拼接。
- 歌声静音移除保持时间长度，不压缩时间轴。输入文件不修改。
- 视频使用实际容器时间戳处理音画偏移；不能只用帧率乘秒数猜索引。

### 4.2 候选不是不可逆裁好的碎文件

每条候选保存源区间、分析上下文、潜在边界和证据；模型通过源音频读取所需上下文。输出区间与分析区间分离，不能把分析用的别人物语音导出。

候选账本保留 `accepted / rejected / unresolved` 三种状态及理由。未解决的真实目标讲话仍算漏检；`unresolved` 不是藏起错误的第四个结果集。

新数据结构建议：

| 对象 | 必需字段 |
| --- | --- |
| `SourceTimeline` | 源指纹、样本率、总样本、通道映射、媒体时间映射 |
| `ReferenceBank` | 样本指纹、组别、质量、原音/UVR 特征、有效讲话区间 |
| `SpeechCandidate` | 稳定 ID、源区间、分析上下文、VAD/字幕来源、边界候选 |
| `TemporalEvidence` | 时间步长、目标/其他/重叠/歌声证据、换人证据、质量与校准版本 |
| `SpanDecision` | 接受/拒绝/未决、最终区间、局部风险位置、决策链与父候选 |
| `ExportRecord` | 音频/文本路径、源区间、STT 状态、增益、全部版本号 |

核心判决接口不接收人物姓名、剧集标签、字幕文本或人工真值；排除人物仅用用户分组及音频。

## 5. 静音、字幕、歌声与重叠的具体处理

### 5.1 静音范围规则

设下限为 L、上限为 U，默认 L=`0.20 s`，U=`0.85 s`：

| 静音长度 g | 处理 |
| --- | --- |
| g < L | 不因这段短静音创建句间硬边界，但仍可检测真实换人 |
| L ≤ g ≤ U | 保留前后两个可判别部分；同一人物证据支持后才合并，保留原有静音 |
| g > U | 硬切，不允许声纹、字幕或上下文覆盖这一规则 |

等于边界的行为固定如表，避免不同函数各自解释。禁止把确认的换人、歌声或重叠空洞当“静音”跨越。被静音移除的歌声不是天然停顿。

静音不是简单“振幅低”。清辅音、轻声与 UVR 残损须结合讲话活动和局部频谱判断；不能将一句话中的弱音全部当作无人讲话。

### 5.2 字幕只做时间辅助

- 使用可靠锚点估计偏移；全局偏移不足时，允许按有足够锚点的局部段估计缓慢漂移，不能用单个字幕强行拉伸音频。
- 处理字幕错集、删减版、片头时长差、重叠字幕、歌词、屏幕字和漏行；不可靠则局部关闭辅助，而不是整段硬套时间。
- 字幕区间内补查 VAD 漏检，边界附近搜索实际停顿或换人。
- 没字幕的对话仍须检测；有字幕不代表一定有人说话。
- 字幕可产生多个候选边界，不提供身份或自动合并许可。
- STT 不使用翻译文本作提示或替换文本，避免文字泄漏造成“看起来识别正确”。

### 5.3 歌声先处理，但减少边缘连带误删

歌声阶段内部采用“粗定位 → 边缘细查 → 确认/未决掩码”的流程，完成后再 UVR。

- 不能把某个 `3 s` 窗口的高分当作其中每个采样点都在唱歌。
- 不能因为两个歌声区间距离较近，就无证据地屏蔽中间完整对话。
- 细查需要适合时间定位的事件证据；不是把原本为秒级分类训练的 PANNs 生硬缩到几十毫秒。
- 未决区域在歌声阶段加做必要复核；仍不明确则标记，后续身份高分不能抹掉这一风险。
- 人说话叠加纯器乐允许继续；人说话叠加他人演唱属于污染，不以分离结果听起来干净为由放行。
- 原片、掩码和理由均可追溯。歌声误删的真实目标话仍计入召回损失。

### 5.4 重叠与连续换人分开

- 重叠是同时存在多个人物讲话；必须保留独立重叠证据，目标检测高分不能覆盖。
- 连续换人可拆成不同完整话段，不应一律丢弃整个长块。
- 只有某一局部发生重叠时，邻近完整、独立的干净话段可以保留。
- 若重叠发生在目标句内部，不能挖掉中间后把剩余音拼成“完整句”。
- 不把目标分离器从重叠里提出来的波形当作合格单人原声。

## 6. 核心模型：参考条件时序身份与纯净度判别器

### 6.1 为什么仍值得研究，而不能承诺解决

普通声纹系统主要学习“整段语音来自谁”，短暂侵入可能被整体池化平均掉。新任务要求学习“给定参考，每个局部讲话事件属于谁；整段是否存在其他声音”。训练目标和可用时间信息都不同。

它仍依赖说话人声学特征。如果原始音频本身无法区分两个声音，再复杂的网络也不能创造证据。模型输出概率、时间分辨率或更多小数位不是正确性的保证。

时序模型可以利用两侧上下文，但不能简单把邻近长句的身份复制给不确定短音。测试和训练必须专门打破这种捷径。

### 6.2 输入

每次分析输入：

1. 当前候选及前后声学上下文的原音、UVR 两种视图；严格对齐。
2. 多段目标参考的原音/UVR 特征、有效讲话掩码、质量信息。
3. 可选排除人物参考，每组独立；缺失是正常情况。
4. 分析范围掩码与允许输出范围；邻近人物的声音可以作为判断上下文，但不能因此进入输出。

候选静音边界继续承担提案作用。模型不是在整集按固定声纹窗随意拼接；必要的底层分块仅用于编码长音频，相邻块重叠复核，不改变最终话段定义。

字幕文本、姓名、集数、已知答案、STT 结果均不作为身份输入。

### 6.3 初始网络结构：先复用，再验证是否需要新骨干

建议原型参数如下，均为实验起点，不是已验证的最佳参数：

- 首选检查本地 WavLM 声纹模型能否稳定导出未池化的帧级隐藏状态，而非只取最终整句向量。
- 当前本地配置为 `WavLMForXVector`，隐藏维度 768、12 层、卷积总步长 320 个 16 kHz 样本，约 `20 ms` 一步。**这是特征间隔，不是人物识别能准确到 20 ms。**
- 将帧级特征投影到约 256 维，建立小型、可离线双向处理的时序模块；初步比较 2–4 层与较小注意力头数，不一次铺开大量结构组合。
- 参考音频保留多段、局部时间特征；用有质量约束的参考集合编码与交叉注意力对照候选，而非把所有参考无差别压成一个均值。
- 原音和 UVR 由共享骨干或明确共享权重的分支编码，融合时带质量与缺失掩码。两者错误相关，不能当作两份独立证据相乘。
- 首轮冻结骨干，仅训练投影和判别头。若已验证训练与标签无误但特征区分力不足，再局部解冻较高层或使用适配器；不能指望更复杂的分类头恢复已经被表征丢掉的信息。
- 在冻结编码器阶段可以缓存特征；解冻后旧特征失效，不得继续用旧缓存冒充新模型训练。

原型分析上下文先比较候选自身和左右各约 2 秒；难例可以扩大到左右各约 5 秒，但不把这些数值设成永久质量门槛。长候选按上下文块编码，边缘证据不得只来自补零区域。

### 6.4 输出必须包含“存在目标”和“存在其他声音”两类独立证据

建议多任务输出：

| 输出头 | 任务 | 注意点 |
| --- | --- | --- |
| `target_activity` | 当前局部是否有目标人物讲话 | 存在目标不等于只有目标 |
| `other_activity` | 是否有非目标人物讲话，包括未提供排除参考的人物 | 不能只识别已登记的排除角色 |
| `speaker_change` | 讲话归属变化的时间证据 | 情绪变化、音高跳变本身不能直接算换人 |
| `speech_boundary` | 讲话起止、弱尾音及清辅音保护 | 不能用声纹置信度直接裁辅音 |
| `span_contamination` | 候选内是否混有他人讲话 | 需对极短局部污染敏感，不能仅做时间平均 |
| `quality_features` | 失真、低信噪比、通道差异等辅助特征 | 用于校准与未决路由，不等于自动真值 |

目标与其他讲话头使用可同时激活的多标签设计；重叠时二者可能同时为真。不能采用“有目标就把重叠也标成目标单人”的标注方式。独立的歌声与重叠模型在初期继续提供证据。

`uncertain` 是经验证集校准后的判决状态，不是声学上真实存在的“第五个人”。对超出训练分布的输入，高 softmax 分数不代表可靠，应保留分布外/质量风险报告。

### 6.5 多参考与排除人物

多参考处理要求：

- 去除完全重复或近重复参考，避免重复上传改变投票权。
- 按有效讲话和录音质量处理参考，不能让音乐或静音时长决定权重。
- 保留情绪/发声方式差异，不因某段轻声离均值远就自动认定它是错人。
- 对疑似混人或参考组不一致给出诊断；不把其他人物样本自动吸收成目标的新风格。
- 在训练中随机改变参考数量、顺序、长度与质量，避免只适应固定参考数量。
- 不承诺任意新增参考都只增不减。验收应检查多数正常新增参考是否稳定增益，以及低质量参考是否引发不可接受的污染。

排除人物作为有标签的竞争证据，而不是固定减去一个分数：

- 每个人物独立建参考集合，保持角色内/角色间分离。
- 同时估计目标、已知排除人物和开放的其他讲话证据。
- 不要求候选一定归入某个已登记角色；允许“非目标，但不知道是谁”。
- 排除组为空、只覆盖部分人物、含音色相似人物，均是必须覆盖的训练和测试条件。
- 若排除参考与目标参考实为同一人或两组无法区分，应报告冲突，不能自动猜用户想保留哪一组。

### 6.6 为什么不把多个模型分数简单加权当主方案

现有 ERes2Net、CAM++、WavLM、WeSpeaker 等保留为基线、特征诊断和必要对照，不继续堆成“全部通过才通过”的串联闸门。

确需融合旧分数时，应在说话人隔离的训练/校准集上学习融合，包含时长、质量和模型相关性；独立报告它相对单模型的增益。学习融合也不是突破保证，不能用第一集的少数正反例拟合权重后宣称通用。

## 7. 身份与边界的联合决策

### 7.1 候选内的处理顺序

1. 获取时间定位的身份、其他讲话、换人、歌声、重叠及质量证据。
2. 将确认或高风险的事件定位到局部，形成多个合理边界假设。
3. 比较完整可输出话段，不用“保留最长高分中间部分”冒充完整句。
4. 对可能新增的前缀/尾句单独保留风险证据，再验证整体连续性。
5. 在用户静音规则与禁止跨越区间约束下选择边界。
6. 对最终实际导出区间再审一次；不能只审切分前的候选。

可用受约束的动态规划/半马尔可夫解码组织候选，但它只组合模型证据，不增加人物身份信息。状态转移先验不能压过明确他人证据，也不能强行填平一个短暂他人片段。

### 7.2 区分三种典型难例

| 情况 | 所需处理 |
| --- | --- |
| 目标长句后有短停顿和目标短尾句 | 尾句有自身局部身份支持、连续性合理、无其他声音；在静音范围内才合并 |
| 目标长句后有别人一个短音 | 局部其他讲话/换人证据阻止合并；找到真实目标终点，不能靠整体高分放过 |
| 前半句别人、后半句目标 | 定位换人后判断后半段能否构成完整原有话段；不能把前半段带上，也不能机械整块丢弃 |

“短尾句与长句同属一人”的证据可结合参考与上下文，但训练要包含“长句目标、短尾音非目标”的反例，禁止学习“挨着目标就算目标”。

### 7.3 局部污染与边界保护不能互相掩盖

- 人物纯净度检查不得仅取平均得分；评估局部最高风险、连续风险区间和候选的受训练污染头。
- 不要求每个清辅音独立产生强声纹，否则会系统性截音。身份主要由具身份信息的语音及邻近声学连续性支持；边界模型保护弱音。
- 若疑似其他人的短音无法可靠定位或区分，不自动给出“纯净”结论；计入未决和召回损失。
- 听得见的侵入即使只有 0.x 秒也算污染，不能因为低于评估容差就豁免。
- 在边界不确定带内优先增加分析，而不是默认向内削掉固定 0.1 秒。
- 检测不到可靠切点时不能用零交叉点冒充人物切换点。零交叉只用于避免波形咔哒，不证明身份。

### 7.4 完整性终审

终审检查：候选首尾是否仍有属于同一句的语音、裁切是否位于音节内部、内部是否有未处理换人、是否遗漏合规短尾句、是否违反长停顿硬切。

字幕可以提醒“这里可能没结束”，但不能据此恢复任何未验证的人声。STT 文字通顺不代表声学完整，也不能作为身份依据。

最终纯净但残缺的话段不能计作“完整正确输出”。若在研发报告中单列，必须明确其失败性质，不混入成功时长。

## 8. 训练数据方案：可靠标注比堆模型更关键

### 8.1 数据来源分层

1. 已有已授权的目标/排除参考与人工确认片段：可用于回归和小规模可行性检查，不足以独自训练通用模型。
2. 可合法用于训练的多说话人语音：提供人物身份与基本跨录音变化。
3. 可合法用于训练的日语表演/动漫风格语音：补足情绪、轻声、短应答、相近音色。
4. 真实有时间标注的对话场景：学习自然换人和无缝接话，防止模型只会识别人造拼接痕迹。
5. 歌声、器乐、噪声与混响：提供排除事件和域扰动，分别审核使用和再分发权利。

公开可下载不等于有训练和分发授权；GitHub 代码许可证也不等于数据或权重许可证。下载前登记来源、许可、大小、用途以及是否可随 EXE/模型发布。

已发现的 AnimeVox 为英文配音且标注为非商业许可，不能把它直接当成匹配日语场景且无授权限制的主训练数据。已存在的动漫声纹权重可以做对照，但不等于已经拥有可用训练集。

### 8.2 先进行数据可用性门禁

在实施模型训练前必须确定：

- 有多少可验证身份的说话人/角色、多少真实对话时长？
- 是否有声音相近的不同人物，以及同一人物跨情绪样本？
- 是否能合法训练、保存检查点以及发布最终模型？
- 谁负责人工核对真值和争议，标注标准是什么？
- 是否有未参与开发的真实场景用于盲测？

如果这些不满足，阶段产物应是数据缺口与补齐方案，而不是宣称已有训练路线可以直接达到目标。

### 8.3 合成训练场景

在合法、身份明确的单人语音上构造下列场景，并保留精确标签：

- 目标单独出现；其他人单独出现；目标完全缺席。
- 目标→他人、他人→目标、目标→他人→目标，包含没有明显静音的接话。
- 长目标句边缘/内部插入他人的短应答，与原有目标短应答形成配对反例。
- 目标人物不同情绪/音量/录音条件下的正例；同音高、同性别、音色相近的困难负例。
- 目标与他人重叠；只有其他人物重叠；讲话叠加歌声；讲话叠加器乐。
- 原音、UVR 处理、压缩、混响、低电平及频谱损伤的成对样本。
- 字幕不出现于身份输入；时间辅助测试单独加入偏移、漏行与错误字幕。

短侵入可分 `50–100 ms`、`100–300 ms`、`300–600 ms` 等压力档，但极短切片未必含可辨认身份，不能给它虚假的“必然可识别”标签。压力测试分别记录是否有足够身份信息。

防止学习人工接缝：正负样本都施加相同拼接工艺、背景和编解码处理；包含无接缝的真实短应答，并单独报告真实场景成绩。人工生成数量再多，也不能代替真实对话验证。

### 8.4 防止数据泄漏

- 先按源录音/场景和人物划分，再裁片与增强；同源不同裁剪不能分到训练与测试两边。
- 参考样本与查询样本不得为同一波形或其增强副本；跨录音、跨场景配对优先。
- 校准集与最终盲测集独立，不能在盲测结果上重新挑阈值或检查点。
- 第一集和此前参与反复反馈的集数只作开发回归。
- 跨作品盲测；有可靠元数据时进一步按声优隔离，并单列同一声优扮演不同角色的难例。
- 已知预训练模型可能见过某些人物，需披露可审计范围；不能凭微调数据隔离就声称完全未知人物。
- 公开测试集一旦参与调试就变成开发集，下轮确认泛化须使用新的封存数据。

### 8.5 数据规模不预先许诺

先用覆盖完整场景类型的小型授权数据做可行性实验，再绘制随独立说话人数、真实对话时长增加的学习曲线。不能认为只增加同一个人物的相似句子就等于增加泛化数据。

几十小时、数百人物只是可能的试点量级，不是已准备的数据、硬性承诺或成功保证；是否扩到更多取决于真实盲测趋势和授权条件。

## 9. 训练目标与实验控制

### 9.1 监督目标

可组合的损失：目标活动、其他讲话活动、换人位置、片段污染、跨情绪身份对比、弱音边界保护与真实未决/质量校准。

形式上可写为：

`L = λt·L_target + λo·L_other + λc·L_change + λp·L_purity + λi·L_identity + λb·L_boundary`

这些权重用于训练任务平衡，不是运行时给几个声纹模型凭感觉加权。初始按梯度尺度与标签覆盖设置，随后只在开发集作小规模消融，记录所有实验；没有数据前不编造最佳权重。

关键约束：

- 目标存在与非目标存在不互斥；重叠标签必须正确。
- 片段污染标签是“任何真实其他讲话侵入”，不能按目标占比多数投票。
- 无人声帧不能参与身份损失，避免背景或静音成为人物捷径。
- 目标缺席样本为必要训练组成，而不是只在测试时碰运气。
- 身份对比样本强调同人物跨风格，以及不同人物近音色；不要用简单随机负例掩盖困难样本。
- 边界有人工不确定带时使用软标签/有效掩码；不把含混标签强行训练成毫秒精确答案。
- 不用待提取片段的模型伪标签不断自训练并自动加入参考库，避免早期错人滚雪球。

### 9.2 渐进训练

T0：确认输入采样率、幅度、通道、特征导出、掩码、标签时间轴都正确；做单批次可过拟合检查和受控合成例检查。过拟合检查只验证实现，不代表泛化。

T1：冻结骨干训练小判别头，对照“相同输入的现有声纹/简单分类器”。若复杂结构并无额外收益，记录失败，不直接扩大网络。

T2：在有足够合法训练数据时，局部解冻或适配骨干，验证是否真正拉开困难正负例；保留跨人物/跨场景测试，监控对原有正确结果的影响。

T3：加入真实换人场景和局部污染任务。若身份改善而污染恶化，不能以平均指标提高为由发布。

T4：在独立校准集选择决策策略，锁定模型、阈值和所有时长规则，再打开封存盲测。

### 9.3 耗时不限，不等于无限重复无效实验

每轮只验证一个主假设，保存配置、数据划分、种子、模型指纹和完整结果。候选方案先过短回归再跑整集，显著失败不继续扩大。

允许更长的离线上下文、对难例增加分析、对训练作充分迭代；不把同一个模型重复跑很多次当成独立证据。随机种子变化也不能当作新的声学信息。

当连续受控实验表明同一机制没有改善，先检查数据/任务/表征假设；没有新证据不继续调局部门槛。

## 10. 验收指标：不能用文件数代替成功

### 10.1 必报指标

| 指标 | 定义/意义 |
| --- | --- |
| 错人片段数 | 含任何已确认他人讲话的输出数量；哪怕只有短音也计错 |
| 目标缺席误报率 | 在完整、确无目标人物的源音频上统计误输出数和每小时误输出；不能只测挑出的简单负例 |
| 他人侵入时长 | 导出区间与非目标讲话真值的交集时长，不包含正常静音 |
| 歌声/重叠污染数 | 违反排除规则的输出数量，独立于错人统计 |
| 完整正确片段精确率 | 完整、纯净且身份正确的片段数 / 全部输出片段数 |
| 目标讲话时长召回率 | 正确保留的目标讲话时间并集 / 全部合格目标讲话时间并集 |
| 完整话段召回率 | 被完整恢复的合格话段数 / 合格话段总数；碎片覆盖不算完整 |
| 完整正确语音秒数 | 只累计完整且纯净的目标语音，去重、不计内部静音来虚增 |
| 边界截音/多带声音 | 分别统计开头截断、结尾截断、前缀污染、尾部污染 |
| 策略排除与机器未决 | 1.2 秒等用户策略造成的排除、模型证据不足分别列出 |
| 重复输出 | 同源重叠覆盖重复计数，不能当召回增加 |
| STT/交付完整率 | 音频正确但缺文本、文本失败、ZIP 失败不伪装成完整交付 |

同时报告 WAV 文件实际总时长和有效讲话时长。一个片段切成五个文件不会提高有效讲话时长，也可能降低完整话段召回。

### 10.2 边界评价

标注的不确定范围只用于不确定位置的评价，不是允许混入他人短音的豁免区。对可听辨的污染和截音逐段判失败；边界平均误差小不能抵消某一个严重错误。

按 `0–0.3 s / 0.3–0.6 s / 0.6–1.2 s / 1.2–3 s / >3 s` 分组报告，另外按轻声、喊叫、近似人物、原音/UVR 差异、是否有字幕、是否有排除参考分组。

### 10.3 精确率约束下比较召回

评估时画“污染风险—召回”曲线，比较同等错误约束下的召回，而不是拿新模型的低门槛与旧模型的高门槛比较。

开发集确定阈值，校准集确定最终策略，盲测前锁定。实际部署仍需要判决阈值；“不靠调阈值优化”指不能以接受更多错人为代价制造提升，不代表机器学习可以没有判决策略。

新模型得分不能直接继承现有 `0.68` 的含义，也不能把余弦相似度写成“68% 概率”。前端若保留阈值输入，必须显示所对应的模型、评分语义和经验证的默认值；没有校准结果前不编造新默认值。

### 10.4 零已知错误不等于未来永远零错误

即使测试中零错误，仍需报告样本量和来源多样性。在近似独立同分布、模型预先锁定的条件下，零错误的 n 个样本，其错误率 95% 上界可粗略用 `3/n` 估计。300 个零错误样本仍只对应约 1% 的上界，不是 100% 保证。

同一集相邻片段高度相关，不能假设独立套用公式；应按源录音/剧集/人物分组报告并做分组重采样。这个统计界限是证据说明，不是宣称产品可以容忍 1% 错人。

用户终极目标保持为无误收、无合格讲话遗漏；只达到更高召回的内部版本标记为“阶段改善”，不能宣布目标完成。

## 11. 最小实验矩阵与停止条件

| 实验 | 只改变什么 | 回答的问题 | 不通过时怎么办 |
| --- | --- | --- | --- |
| E0 冻结基线复现 | 不改算法，固定输入参数与资产 | 当前可复现结果究竟是什么 | 先解决版本/输入不一致，不能直接比较文件数 |
| E1 分阶段理想裁决 | 评估器内替换一个或两个判决 | 改哪里有足够恢复空间 | 没空间的阶段不优先投入 |
| E2 完整候选账本 | 增加追溯和非破坏性候选保留 | 目标讲话是否仍不可达 | 修正候选来源和预过滤边缘 |
| E3 冻结特征判别 | 固定骨干，比较简单头与时序头 | 时间信息/学习任务是否提供收益 | 排查数据/标签；不堆深度掩盖表征不足 |
| E4 表征适配 | 在 E3 上局部微调 | 能否分开近音色人物与跨情绪正例 | 若盲域退化则不采用，补数据或更换有依据的骨干 |
| E5 局部污染与边界 | 添加专门任务及真实短音测试 | 是否减少混音且不增加截音 | 单独回退任务，禁止拿整体均分遮盖 |
| E6 多参考与双视图 | 有控制地去掉/加入各项 | 是否真增益，是否参考越多越差 | 删除无收益复杂度；保留有效最小结构 |
| E7 完整流水线盲测 | 冻结全部参数跑未见场景 | 整体正确完整时长是否真实增加 | 不替换正式引擎，标明失败类型 |

每次消融使用同一数据划分和导出政策；必要时重复不同训练种子，报告波动。不能每次换参考、字幕和下限，然后把数量变化全归功于模型。

所有测试中的“人工真值”仅用于评估，不能参与模型选择以外的正式推理。盲测报告出炉后才允许查看错误细节；一旦用它调试，就不再称为盲测。

## 12. STT 与导出：不能在最后再次误删正确音频

- 最终区间冻结后才转写；身份模型不读 STT，STT 不决定人物是谁。
- 现有“STT 返回多个片段即疑似换人”的拒绝分支，须在声学纯净度终审实现并验证后移除。不能只删除这道门而放弃原本由它偶然拦住的错例。
- STT 返回多个文本片段，允许在同一个已审定音频区间内组合文本，不依据文本分段重切人物。
- STT 失败时进行有界重试或明确标记 `audio_verified_text_pending`，保留已验证音频；不能改判成“非目标人物”。
- 待转写音频和最终完整交付分开报告。最终 WAV/TXT 配对不能用空文本或翻译字幕伪造完成。
- 日文仍输出日文；姓名、专有名词错误单独计入文本质量，不影响身份统计，也不能掩盖文本未达标。
- 响度整理使用可追溯增益和削波保护，不做变调、语音生成或无必要音色重建；不能把噪声和失真无限放大。
- 导出波形也要检查明显 UVR 损伤。时间覆盖完整但实际尾音已被分离器抹掉的结果不能算声学完整。
- 保持批次统一 ZIP；用临时文件后原子完成，取消/失败保留可追溯已完成项，不生成误导性的“全部成功”。
- 视频输出必须记录选定音轨、源时间范围与编码策略，避免导出时带入另一条语言音轨。

## 13. 工程拆分与接口迁移

以下是未来拟新增模块，不代表本次已经创建代码：

| 拟议模块 | 职责 |
| --- | --- |
| `extractor/timeline.py` | 源时间、重采样和媒体时间戳映射 |
| `extractor/candidate_ledger.py` | 候选来源、状态转换、稳定 ID 与漏失追踪 |
| `extractor/reference_bank.py` | 多参考质量/去重/分组及特征缓存 |
| `extractor/temporal_identity.py` | 参考条件时序模型推理，返回证据而非直接导出 |
| `extractor/decision_policy.py` | 版本化校准、开放非目标判断与未决路由 |
| `extractor/boundary_decoder.py` | 用户静音规则下的边界选择、纯净度与完整性审查 |
| `training/` | 数据构造、划分、训练、校准和模型卡；不进入正常运行依赖 |
| `evaluation/` | 真值核验、分阶段审计、消融、盲测报告；与推理隔离 |

迁移原则：

1. 先加可观测性与测试接口，不重写整份 `pipeline.py`。
2. 旧引擎配置固定，内部用开发选项启用新引擎，不给用户新增“标准/严格”等质量档位。
3. 以模块接口替换现有身份/边界流程，不把新模型叠在所有旧拒绝门之后。
4. 歌声、重叠、字幕和短句导出政策变更单独提交和评估，保持因果可解释。
5. 新旧结果按源时间对齐比较，不依赖输出编号。
6. 正式更换前保留可启动的旧版本和可回滚模型版本；不移动或修改其他程序资源。
7. 本地开发与远端发布分开。只有用户明确要求上传才推送或发 Release。

### 13.1 运行时进度与日志

报告真实阶段、已处理/总候选数、音频扫描位置、当前模型、已用时间和当前操作。未知总量就显示已扫描时长，不能一直挂在某个固定百分比而不给解释。

每条拒绝需记录：拒绝原因代码、对应时间区间、相关证据与版本。耗时分析可复用缓存，不能每次从头分离整集。

取消在安全的分块边界生效；训练/推理进程分离，避免用户关闭界面后留有不明确的后台任务。

### 13.2 原有“输出全部单句”模式

保留此模式，但明确绕过的是目标身份筛选，不是歌声、重叠与完整边界检查。没有目标参考时使用不依赖目标身份的换人/边界能力，不能给时序目标模型随便填一个人物。

模式产生的人工筛选材料不计入指定人物自动提取的精确率/召回率，也不能混入正式目标人物输出。

## 14. 测试清单

### 14.1 确定性单元/性质测试

- 静音长度恰好等于 L、U，以及上下各一个时间步。
- 重采样往返、UVR 延迟、分块补零、浮点秒与样本索引转换。
- 字幕整体偏移、局部漂移、错集、空字幕、重叠、歌词和屏幕文字。
- 字幕不得越过硬停顿、确认换人、歌声和重叠区间。
- 空参考、纯音乐参考、同人物多参考、重复参考、疑似混人物参考。
- 排除组为空、部分覆盖、顺序变化、同一人被放入目标与排除组。
- 输出片段内目标/他人活动同时为真的逻辑；不得因目标活动高而忽略其他活动。
- STT 多文本片段不改变身份；STT 失败不删已验证音频。
- 取消、断点恢复、缓存失效、ZIP 失败、保存路径和视频时间轴。
- 所有候选拒绝都有可追溯原因；所有新输出有来源，禁止凭空生成片段。

### 14.2 必做声学回归

- 一句中极短停顿，不错误切成两半。
- 中间范围停顿，同人物合并、不同人物分开。
- 超过上限的停顿，即使同人物或同字幕也不合并。
- 首尾清辅音、轻声、短应答、喊叫、哭腔和音高突变。
- 目标长句 + 他人一个短音；他人长句 + 目标短音；目标 + 他人 + 目标。
- 只有其他人物讲话，特别是相似音色人物；必须允许零输出。
- 器乐+讲话、只有器乐、有人演唱、讲话与歌声同在、多人重叠。
- 原音与 UVR 身份证据不一致、UVR 引入损伤、原音背景相似但人物不同。
- 少参考到多参考、干净参考到含背景参考、排除角色覆盖不足。
- 第 2 节中的自我介绍、下一人物、混合话段用作历史回归，不写时间点特化逻辑。

### 14.3 必做泛化验收

至少涵盖未参与开发的源场景、不同人物、不同作品/录音条件，以及无字幕、无排除人物两种默认可用场景。实际数据数量须随数据审计确定，不能拿一个未见片段替代整体泛化评估。

单位测试通过只能证明代码逻辑；音频指标提高才证明任务效果；完整人工核验才支持“这批输出未发现错误”。三者分开报告。

## 15. 本地资产、依赖与磁盘策略

### 15.1 已看到的资产

当前配置引用 ERes2Net、CAM++、WavLM、WeSpeaker、PANNs、重叠检测与 STT/UVR 资源。本次还在本地看到动漫 char/va 声纹权重、ONNX 文件和 VoiceFilter 权重。

- `model/speaker/wavlm-base-plus-sv/`：已有约 405 MB 十进制权重及配置，可优先验证未池化特征接口。
- `models/anime-speaker-char/`、`models/anime-speaker-va/`：各有约 83 MB 的原权重与约 83 MB ONNX；先复用做对照，不重复下载，也不假设之前没试过。
- `models/conv-voice-filter/`：已有约 217 MB 权重及源码/配置；文件存在不等于已验证可用，不把它作为默认训练音频生成器。

以上是路径/文件存在与配置检查，不是本次完成了所有模型加载或效果测试。首次实验前应验证兼容性、前处理、来源许可和模型指纹。

### 15.2 下载与环境原则

- 本次方案阶段不下载任何模型或数据。
- 实施时先查配置路径和现有缓存，再列出真正缺失项、用途、授权、下载量和展开空间。
- 不重装现有 CUDA/PyTorch，不为了训练实验升级正式运行环境。
- 新训练依赖若与现有运行环境冲突，使用项目内隔离环境；创建和大规模下载前说明空间与兼容性影响。
- 正式软件只带推理所需依赖；训练数据、训练优化器状态和实验脚本环境不随 EXE 打包。
- 永久依赖缓存继续保留。模型版本升级用轻量元数据使相应缓存失效，不让每次启动都重新扫描所有模型和导入大框架。

### 15.3 空间账本

以下为十进制 GB 的理论量级，不是本次需要下载的清单：

- 16 kHz 单声道 PCM16：每小时约 0.115 GB；100 小时约 11.5 GB。
- 同样音频 float32：每小时约 0.230 GB，原音+UVR 双份再乘二。
- 单层 768 维、50 帧/秒、float16 特征：每小时约 0.276 GB；12 层、两视图约 6.64 GB/小时，全部缓存 100 小时会达到约 664 GB。

因此不能默认缓存所有层、所有视图、所有实验。只缓存选定的冻结特征或按需计算，记录模型指纹；解冻训练采用在线编码。使用源区间索引，避免每次实验复制整集 WAV。

研发缓存必须单列并设置容量上限，先根据实际剩余空间提出预算；达到上限暂停新增缓存或由明确策略清理本轮可重建文件。不能自动删除用户输出、原始媒体、参考音频、标注真值或其他软件文件。

永久保存：设计、配置、划分、真值、结果表、必要失败样例索引和模型卡。可重建缓存：临时裁片、冻结特征、临时增强音频。大型音频和权重继续不进入 Git。

### 16.2 发布门禁与终极完成标准分开

阶段改进版的最低门禁：

1. 固定回归集中已确认正确完整的覆盖不退化；修复旧错误不受“不退化”规则阻止。
2. 所有已知他人短音、连续换人、歌声与重叠错误无新增放行。
3. 独立场景人工核验未发现错误输出，且完整正确讲话量确有增加。
4. 增益不是来自重复、碎切、加静音、降低旧阈值、修改评估分母或放宽完整性标准。
5. 批次导出、取消、STT 状态与桌面兼容均通过相应测试。

这些只够称为“经过验证的阶段改进”，不自动等于用户的最终要求完成。只有在明确范围的完整真值集上达到没有误收、没有合格讲话遗漏，才可以说“该测试范围内达到目标”；仍不得承诺任何未来录音绝对如此。

## 17. 风险与应对

| 风险 | 如何识别 | 应对 |
| --- | --- | --- |
| 现有表征根本分不开相似人物 | 完整候选下困难正负例仍重合，冻结头无泛化收益 | 任务数据与表征微调；无证据不继续改阈值 |
| 语音信息本身不足 | 多人/严重失真/极短无身份线索，人工也无法稳定判断 | 明确未决；不靠重复推理制造确定性 |
| 为防污染而全面拒绝 | 精确率高但完整话段召回很低或零输出 | 双指标门禁；零输出不是成功 |
| 为提高数量而保留碎片 | 文件数升高但完整话段召回、有效时长不升 | 去重和完整性评价，取消文件数作为主指标 |
| 时序平滑吞掉短换人 | 对目标长句夹短他人音失败 | 局部污染任务、真实短应答压力测试，不允许平滑覆盖证据 |
| 多参考导致身份漂移 | 新增正常参考后错人增加，重复样本影响决策 | 集合编码/去重/质量校准，专门多参考消融 |
| 排除人物掩盖开放集缺陷 | 有 5 个排除组表现好，移除后崩溃 | 无排除、部分覆盖、未知人物独立测试 |
| 模型用背景判断人物 | 同背景跨人物误认、跨背景同人物漏检 | 对照交换背景，跨录音参考，成对增广 |
| 合成数据接缝捷径 | 合成集好、自然接话差 | 匹配正负处理工艺，真实对话单独门禁 |
| 过度分离损伤音色/辅音 | 时间覆盖正确但波形语音缺失，原音/UVR 分歧大 | 保留原音证据、质量审查；不以变声或生成修复掩盖 |
| 训练数据授权不清 | 无可追溯许可、仅有代码许可证 | 不纳入训练或不发布受限权重，先补齐授权 |
| 声优相同但角色不同 | 身份模型只按声优聚合 | 明确参考角色任务，单列难例；不能保证表演声线相同仍可区分 |
| 过度拟合已反复使用的第一集 | 开发片段很好，未见集数/人物退化 | 冻结跨场景与跨人物盲测，披露预训练数据未知项 |
| 复杂系统不可维护 | 多处隐藏拒绝门、说不清哪个阶段丢失 | 单一账本、集中决策策略、分阶段消融、删除无收益分支 |

任何样本级“置信度”都不能被包装为个人身份的绝对正确概率。校准只在相应验证分布下提供统计依据；分布变化、人物相似度和标注错误仍可使其失效。

## 18. 明确不纳入主线的做法

- 不把字幕角色名、台词剧情或画面里出现的人物当作自动身份真值。
- 不默认增加视频人物识别、唇形识别或外部大模型 API；纯音频输入必须可用。
- 不用 TSE/VoiceFilter 的“输出有声音”证明目标存在；目标缺席和错提取必须单独验证。
- 不用目标分离器生成的波形直接替代真实 UVR 输出来训练克隆模型。
- 不增加无明确互补性的声纹模型、全局聚类或匿名分轨投票。
- 不依赖测试集特定人物、时间点、字幕句子或声音长度写特例。
- 不将低质量、缺少文本或待审样本悄悄混入正式训练 ZIP。
- 不以“算得久”“用了很多模型”“更复杂”代替效果证据。

未来若这些方向出现确实不同且可验证的新信息，可作为独立研究，不影响本方案的主线和已冻结基线。

## 19. 实施前需要落实的事项

无需现在停止设计等待回答；以下是后续实施的明确决策点：

1. **短句导出政策**：建议关闭固定 `1.20 s` 身份无关长度下限，改为可选训练导出过滤。实施前确认实际默认行为变化。
2. **真值与数据授权**：明确可用于完整标注、微调和封存盲测的数据范围，以及人工核对安排。这不能由程序自动“猜”出来。
3. **资源预算**：训练数据下载与新增缓存上限，是否需要项目内隔离训练环境；不移动现有共享模型。
4. **实施权限**：用户已要求执行方案；代码、必要模型与本地实验在任务范围内。上传远端仍须用户单独授权。

不需要用户提供所有排除人物，不需要每次使用标注全片，不要求填写人物姓名；这些都不是新方案的前置条件。

- [ClearerVoice-Studio](https://github.com/modelscope/ClearerVoice-Studio)：有多类语音处理研究与预训练模型。其简易推理接口的目标提取与训练目录中音频参考条件模型需区分，不把视听模型当纯音频替代品。
- [Anime Speaker Embedding](https://github.com/litagin02/anime_speaker_embedding)：区分 char/va 两类训练目标，已有本地权重；领域相近不代表本项目短音污染、未知角色与完整召回已解决。
