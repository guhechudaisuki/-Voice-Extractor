## §0 一页结论

### 核心判断

项目现在卡在一个**局部最优**里：每发现一类错句，就新增一层"救援/合并/兜底"路径去把它捞回来，而每一层新路径都是用第一、二集的试听结论调出来的。第三集是唯一一次真正的跨集检验，结果是 28 段里 10 段整句非目标 + 1 段部分非目标（约 61% 干净）。错的句子高度集中在新加的那些路径上：走"定位器"的 6 段里错了 5 段，走"分类器救援"和"字幕补全"的也各错一半左右。而完全没走特殊路径的段（第 6、13、15 句）一句没错。

也就是说：**不是声纹判断力不够，而是"为了让输出变多"而加的那些补救路径，比主判定更容易出错，而且没有独立的准入标准。** 在这个结构下再加第 28 层路径，只会把错误率继续往上推。

### 我的做法（五步，按顺序不可颠倒）

1. **先让评估可信**：固定基线、建立句子级标签库、把口径从"批次序号"改成"源音频 sha256 + 时间区间"，把每一段输出的裁决路径和分数量化出来（决策台账）。
2. **立刻止血**：引入"主输出 + 待审"双通道。凡是通过救援类路径进入的段，默认不放进主输出，先给人听。这一步不改任何判定逻辑，因此零风险，且能让下一批输出立刻变干净。
3. **再谈身份判定升级**：用你已确认的标签建"已验证声纹库"，把当前一堆硬阈值换成一个可标定的融合裁决器（kNN/AS-norm + 逻辑回归多特征融合），并在留一集协议下评估。
4. **然后才是召回**：召回现在是**没被测过**的。先用分层抽样把"漏掉了什么、漏在哪一步"量出来，再只修最大的那一类，且新召回路径一律只进待审通道。
5. **最后做数据质量**：STT 守卫、A/B/C 分级、GPT-SoVITS `.list` 导出、数据集报告。

### 两个必须由你拍板的产品决定

**决定 A：双通道。** 输出 ZIP 分成 `主输出/`（只在通过准入的段）和 `待审/`（存疑但可能有价值的段）。主输出的目标是"你打开就能直接进训练集，几乎不用逐句听"。代价是默认输出数量会先下降——这与你的硬要求"输出比以前更多"表面冲突。

**决定 B：把"更多"重新定义。** 我建议把验收口径从"输出段数更多"改成"**你确认正确的段数和干净分钟数更多**"。第三集现在的 28 段里有 11 段是废的；一个 20 段但 19 段正确的输出，对你的实际价值高于 28 段里 17 段正确。如果你不接受这个重新定义，那么本计划里 Phase 2 的准入标准需要放宽到"宁可错杀也要多"，我会相应调整——但那样第三集的那种精度退化就会继续。

### 1.2 评估本身不可信（比错误更严重的问题）

这一条决定了前面所有数字的可信度，必须优先修。

**标签泄漏。** `evaluation/train_anime_t3_reviewed.py` 里，试听结论中的修订一律标记为 `force_train`，全部进训练集。而 v9 报告（`work/anime_t3_reviewed_20260928_v9/training_report.json`）自己写着 "Latest corrections belong to training, not held-out success claims"。评测集只有 20 正 2 负，而且排除阈值 `reject_threshold = min(-1.0, 二分值, min(all_positive_evidence) - 0.25)` 里的 `all_positive_evidence` 包含 test 分片。这是**用测试集定阈值**。

**划分单元错误。** 现在的分片按"集内 5 秒间隔的时间组"切，训练和测试可能来自同一集、同一场景、同一录音条件。这只能回答"同一集里能不能分开"，不能回答"换一集还行不行"。第三集已经用实测证明这个差距很大。

**批次重叠。** 重跑的 `567448` 用的是 v9 模型（训练数据含第三集），所以在第三集上的表现是**样本内**的，不能当泛化证据。

**召回完全没测。** 第三集的漏斗是：253 段原始 VAD → 259 个干净语音孤岛 → 254 个说话轮次 → 48 段 STT 前身份通过 → **最终 28 段**。48 到 28 之间丢了 20 段，**没有任何记录说明为什么**。而久美子是主角，一集只有 28–55 句台词这个量级本身就很可疑——真实台词数很可能远高于此。我的**推测**是：召回不足可能比精度问题更严重，但这一点当前无法证实，必须先测。

### 1.3 试听回路又贵又有损

现在的流程是：跑完 → 打包 ZIP → 我读 → 你逐句听 → 你在对话里口述"第 N 句非目标 / 前 X 秒非目标" → 我手工写成 JSON。问题：

- 标签挂在**批次序号**上，换一次运行序号全变，旧标签作废。
- **没有记录你实际听了哪些段**。所以 21–28 句到底听过没有，现在无法确认——这直接影响到 1.1 那张表的分母。
- 桌面界面（`launcher/voice_extractor_desktop.py`，tkinter + ttk）**没有音频播放**，你必须在资源管理器里对着序号找文件。
- 反馈靠聊天口述再转写，多一次转录就多一次出错机会。

### 1.4 一个具体的可疑机制（合并路径）

读代码（`extractor/pipeline.py`）发现三处需要核实的地方：

1. **`_install_acoustic_identity_certificate`**：只要片段带 `post_target_silence_merge` 标记，就直接签发 `verified_target_silence_merge` 证书——**不看合并进来的边缘是谁**。
2. **`_stt_fragment_identity_veto`**（约 1395–1432 行）：同样只要带 `post_target_silence_merge`，即使有 ≥2 个 STT 片段也**返回 None（豁免）**。这绕过了你在 `docs/stt_boundary_policy_20260925.md` 里定的策略——多片段释放必须要有精确跨度的 `local_identity_audit.passed`。
3. **合并入口有两处**：`_repair_final_sentence_boundaries`（约 2155 行，合并点在 2605 行）和短静音合并（约 2660 行，合并点在 2801 行）。第二处的边缘准入条件是一组硬阈值（时长 ≥1.20、eres ≥0.50、camplus ≥0.50、paired_reference_median ≥0.40）。

第三集第 8 句同时带 `post_target_silence_merge` 和 `verified_target_silence_merge`，但**没有** `final_same_speaker_*` 字段，所以**推测**它走的是第 2801 行那条路。这一条需要用 Phase 1.3 的重放来确认，不先下结论。

如果确认，那就是一个结构性问题：**"合并"这件事本身获得了自我认证的权限。** 一段非目标语音被合并进来之后，系统会自己给自己发一张"已验证"证书，之后所有下游检查都放行。

### 1.5 工程上的约束

`extractor/pipeline.py` 共 6427 行，`run()` 约 1700 行（从 4522 行附近开始），`run_many` 在 6252 行。没有跨运行的阶段缓存，只有内存里的 `_tail_scorer_cache`。所以每次改一行逻辑都得重跑 23 分钟。这不是洁癖问题——它直接决定了"每轮迭代的成本"，也是你会觉得"无休止试验"的根本原因。

## §2 目标与度量

### 2.1 主指标

| 编号 | 指标 | 目标 | 说明 |
|---|---|---|---|
| M1 | **主通道整句精度**（留出集） | ≥95% | 只算"整句都是目标"；部分错算错 |
| M2 | 主通道部分错段数 | ≤1 段/集 | 部分错对训练数据的破坏不亚于整句错 |
| M3 | 确认正确的段数 / 干净分钟数 | ≥ 基线 | 这是"更多"的新口径（见决定 B） |
| M4 | 召回估计（含 CI） | 基线 +10 个百分点，且 CI 不重叠 | 必须先能测，才谈得上改 |
| M5 | 每听音 1 分钟得到的干净分钟数 | ≥ 基线 ×1.5 | 衡量试听效率 |

**硬约束（违反即为失败，不看其它指标）：** 主通道内歌声段 = 0，多人重叠段 = 0。

### 2.2 统计规则

- 精度一律报 **Wilson 区间**，不报裸点估计。28 段上的 61% 的真实含义是"可能从 42% 到 78%"，这个宽度本身就是要修的问题。
- 零错误时用**三倍法则**：0/60 错误 → 95% 上界约 5%。
- 留出集总量目标：验证集 + 测试集合计约 120 段。若错误 ≤2 段，95% 上界约 5%，刚好够支撑 M1 的 95% 目标。
- **小样本上不比较两个相近的数字。** 4 段的 25% 和 3 段的 33% 之间没有区别，不要拿它当依据。

### 2.3 评估纪律（这几条比任何算法都重要）

1. **只有你的试听算标签。** 单元测试数、输出文件数、任何模型自评都不算。
2. **留出集只用一次。** 用来调参的集不许再当测试集。
3. **先影子模式，后启用。** 任何新裁决逻辑先并行跑、只出对比报告，不影响输出。
4. **每个新机制都要有开关和回滚点。**
5. **不按台词内容、不按时间点特化。** 这条是你的硬要求，我在计划里没有任何一步违反它。
6. **新的召回路径只能进待审通道**，不能直接进主输出。
7. **改完必须能一句话说清"为什么这次会更好"**，说不清就是试错，不做。

## §4 数据划分与评估协议

### 4.1 划分

按**素材 sha256** 划分，不按批次、不按时间段。

| 用途 | 集数 | 理由 |
|---|---|---|
| dev（开发调参） | ep01、ep02、ep03 | 已有你的试听结论；ep03 是当前最难样本，作为压力测试 |
| validation | ep05、ep10 | 未被试听过，与 dev 不相邻，含合奏场景 |
| test | ep08、ep12 | 只在 Phase 4.3 用一次，此前任何参数都不得看这两集 |
| reserve | ep04、ep06、ep07、ep09、ep11、ep13、OVA | 验证集不够用时再启用 |

**需要说明的历史事实：** ep04–13 在 2026 年 8 月用早期版本（`cc8757`、`534b96`）跑过，机器上有旧输出，但**没有任何试听标签**。这不构成泄漏（模型没见过标签），但别把旧输出当成当前版本的参考基线。

### 4.2 标签复用规则

- 标签以 **(媒体 sha256, 起止时间, 层级)** 为键存储，与批次无关。
- 同一段音频在新旧两次运行中都出现时自动继承标签（跨度 IoU ≥0.5 继承；边界变化 >0.5 秒标记"需复核"）。
- **参考音频溯源检查**：如果某个参考 wav 是从 validation/test 集剪出来的，必须把对应时间段从评估里剔除。Phase 0.4 先做一次一致性检查。
- 你提供的参考目录 `京吹原片音频\kumiko\` 里有一个 `.mp3`（"2年間ずっと思ってきたけど でも、どうしてもそこに届かなかった"）。**需要你确认它出自哪一集**——若来自 ep08 或 ep12，那两集就不能当测试集。

### 4.3 统计

- 点估计一律配 Wilson 95% 区间。
- 0 错误时用三倍法则给上界。
- 召回用分层估计，见附录 B。
- validation + test 池合计目标 ≥120 段；若达不到，应把目标改成"主通道 0 整句错 + 报上界"，而不是硬报一个漂亮数字。

#### 2.5 验证一：B0 vs C1（留出集）

**目的：** 第一次在未见过的集上拿真实数字。

**做法：** 在 ep05 与 ep10 上各跑一次（你批准后；每次约 23 分钟），B0 与 C1 都跑，产出去重后的并集待审包。**你只听一遍并集**（两侧共有的段只听一次），用 1.2 的界面标注。然后 `compare_batches.py` 出报告。

**关键纪律：** 这一步产出的标签落在 validation 集，之后**可以**用于调参；但 test 集（ep08/ep12）仍然不许碰。

**你的投入：** **约 30 分钟**（估两集约 100–150 段，同一集去重后按每段 10 秒计）。

#### 2.6 门槛

主通道 M1 ≥95%（若样本不足则报上界）；M2 ≤1；歌声/重叠 = 0；legacy 等价性通过。不达标则**不启用 conservative**，先回去看报告，最多允许 2 次预先注册的迭代。

### Phase 3：身份判定升级（4–6 天，你的时间约 20 分钟）

原则：**先用你已确认的标签建可信的参照，再谈换算法。** 没有已验证声纹库，任何打分改进都无法验证。

#### 3.1 已验证声纹库

**目的：** 把当前"6 个参考 + 5 个单文件排除"这种脆弱配置，换成一组有质量控制的声纹。

**做法：** 只从 **dev 集**里你确认正确的段中，逐段提取嵌入，做自检（互相似度分布、离群剔除），存为 `models/voice_bank/<profile>/`：`target.npz`（正样本池）与每个排除组一个 `negative_*.npz`。同时保留原始参考文件作为"锚点"。

**验收：** 声纹库内部一致性能报告（目标池内平均相似度 vs 跨组相似度）；剔除的离群段要列出来供你抽查。

**风险与回滚：** 声纹库是从 dev 集建的，因此 dev 集上的表现从此**不再是泛化证据**——这一点必须写进报告，并且验证只能靠 validation/test。

#### 3.2 kNN / top-k / AS-norm 打分

**目的：** 也许不需要更复杂的模型，只需要更好的**打分方式**。当前用固定阈值比较单点相似度，对小样本、录音条件变化很敏感。

**做法：** 在 1.3 缓存的嵌入上（不重算，零额外成本），评估几种打分：

- kNN（对目标池 top-k 平均）替代单参考相似度
- AS-norm（用一集内的其他说话人作为 cohort 做归一化）
- 两者组合

**严格评估协议：** **留一集（LOEO）**——在 ep01 上调、ep02+03 上测，然后换 ep02 调、ep01+03 测，再换 ep03。只有**三集全赢**才采纳。这条协议是为了避免又出现"在某两集上调出来、第三集崩掉"的局面。

**验收：** LOEO 三集全赢 + Wilson 区间不重叠（或样本不足时明确说"分不开"）。

**风险与回滚：** 打分方式改变会影响所有下游阈值。回滚 = 保留旧打分函数，用一个常量切换。

**你的投入：** 0。

#### 3.3 负样本聚类与"这是谁"报告

**目的：** ep03 第 11 句的排除余量高达 0.341 却仍然错了——**推测**是有一个不在排除集里的相似女声（京吹里女角色很多，这个可能性很高）。当前机制无法表达"未知的相似女声"。

**做法：** 把所有被拒绝的段做嵌入聚类，挑出**高相似度但被拒**的聚类，生成报告："这一簇有 37 段，平均相似度 0.52，与目标参考相似度 0.61，可能是同一个未知角色"。你在 1.2 界面里填的"这是谁"可以进一步命名它们。

**验收：** 报告能让 11 句所在的那一簇显现出来（若存在）。

**你的投入：** **约 10 分钟**——看报告，决定是否要为某个簇补一组排除音频。

#### 3.4 融合裁决器（影子模式）

**目的：** 把现在散落在代码各处的硬阈值，换成一个**可标定、可解释、可开关**的裁决器。

**做法：** 逻辑回归，特征 ≤15 个（各模型相似度、排除余量、top-k、AS-norm 分数、时长、STT 片段数、静音合并标记、孤岛层级等）。要求：①每个特征的系数符号必须符合直觉，符号反了就去查数据而不是照单全收；②在**折外预测**上做 Platt 标定，输出 `p_main` 与 `p_review` 两个工作点；③**先只跑影子模式**，写进诊断字段与台账，不影响输出。

**验收：** 影子模式下报告"若按该裁决器切分，dev 三集的精度/召回会是多少"，与当前规则对比。**只有明显更好、且方向与准入表一致时**才考虑启用，且启用后必须重跑 Phase 2.5 的验证。

**风险与回滚：** 15 个特征在 ~200 个样本上就有过拟合风险。因此限制特征数、要求符号可解释、要求折外标定，并且**默认不启用**。

#### 3.5 本地分类器：修好或退役

**目的：** `models/anime_t3/classifier_v2.pt` 当前状态很尴尬：它在 ep03 上出过错误的救援（第 3 句），而且只要你换参考音频就整体关闭、**不回退**，界面上也没有醒目提示。同时 v9 的训练把修订标签全塞进训练集、用测试正样本定阈值、划分是集内时间组——这些都要改。

**做法（二选一，我倾向后者）：**

- **修**：改成片段级或多示例学习（MIL）目标；留一集早停；阈值绝不用测试数据；对 ≥3 个窗口做中值平滑。
- **退役**：如果修完后在 LOEO 里赢不过 3.2 的 kNN/AS-norm，就把它从主判定里拿掉，只在诊断里保留。

无论哪条，**界面必须在分类器因参考变化而关闭时给出明确提示**（当前是静默关闭，这对排查非常不友好）。

**你的投入：** 0。

#### 3.6 验证二

在 validation 集上重跑，**只听新出现的、未标注过的段**（已验证过的标签直接复用，这是 1.1 标签库的直接收益）。出报告，过门槛才进 Phase 4。

### Phase 4：召回（3–6 天，你的时间约 45 分钟）

#### 4.1 把召回损失分桶

用 Phase 1.5 的抽样结果，把漏掉的段归类：VAD 阶段就没检出 / 被歌声检查误杀 / 被重叠检查误杀 / 被说话轮次切碎 / 被声纹判定拒掉 / STT 前通过但最终丢失（那 20 段）/ 没被任何机制提及。

**这一步的输出必须是一张带数字的表**，而不是印象。

#### 4.2 只修最大的一桶

**纪律：** 一次只改一处。新召回路径**只能进待审通道**（§2.3 第 6 条）。改完用 `--replay` 在 dev 上快速看，再上 validation。

**特别关注那 20 段：** 如果"STT 前通过但没有输出"这一桶是最大的，那说明问题不在身份判定，而在 STT 之后的某个过滤/边界步骤——这类 bug 通常修起来性价比极高。

#### 4.3 最终测试

在 ep08 与 ep12 上，用 `--allow-test` 跑 **C2** 与 B0 各一次（各约 23 分钟 ×2 集 = 约 1.5 小时）。你标注并集。**这是唯一一次测试集使用**，结果无论好坏都如实写进报告并作为发布依据。

**如果结果低于 M1：** 不发布为默认，保守档保留为实验选项，回到 §7 的停止条件。

**你的投入：** **约 45 分钟**。

### Phase 5：数据集质量（2–3 天，你的时间约 10 分钟）

#### 5.1 STT 守卫

**目的：** Whisper 会幻听、会重复、会在长静音里产出固定套路句（`ご視聴ありがとうございました` 之类）。你已有 `docs/stt_boundary_policy_20260925.md`，这里做的是**事后标记**：

- 日语输出强制日语（语言锁定）。
- 字符数/秒 落在合理区间之外 → 标记。
- 重复 n-gram 检测、已知幻听短语表 → 标记。
- 记录置信度字段（若有）。

**注意：只标记，不删除，不影响身份判定。** 你下载时可以选择"排除已标记"。

#### 5.2 质量分级 A/B/C

- A：无削波、RMS 在合理区间、UVR 残留伴奏低。
- B：轻微问题。
- C：明显问题（削波、残留乐器、时长过短）。

分级只用于**给你排序和过滤**，不参与身份判定。

#### 5.3 GPT-SoVITS `.list` 导出

若下游确实是 GPT-SoVITS（同级目录有 `GPT-SoVITS-v2pro-20250604`，这与我推断一致），则导出 `.list`：`vocal_path|speaker_name|language|text`。**语言码要按你本地那个版本的约定写**（v2 与后续版本对 `ja`/`zh` 的写法可能有别），需要你确认一次。

**你的投入：** **约 5 分钟**——确认下游工具与语言码约定。

#### 5.4 数据集报告

每次导出附带一页：总时长、段数、A/B/C 分布、时长直方图、STT 字数分布、覆盖率（相对 VAD 检出的语音总量）。

## §10 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| **样本太小**：ep03 只有 28 段，置信区间宽达 42%–78% | 容易得出错误结论 | 一律报 Wilson 区间；不比较相近数字；validation+test 池凑到 ≥120 段 |
| **标注疲劳**：听 100+ 段会走神 | 标签质量下降，污染训练与评估 | 盲听模式；每批不超过 60 段；随机抽 5% 让你重听一遍测一致性；一致性 <90% 则该批作废 |
| **阶段缓存陈旧**：改了代码但缓存命中 | 得出"改了没用"的错误结论 | 阶段版本常量 + git 提交号双键；`--no-cache` 逃生口；"改版本必须失效"的测试 |
| **过于保守**：双通道把太多段推到待审 | 你的听音量增加，违背"更多"的初衷 | S2 停止条件；准入表最多 3 个参数；每阶段报告待审段中被证实正确的比例（当前样本内估计约 7/17） |
| **声纹库被污染**：某段错标进了目标池 | 后续全部判定被带偏 | 自检离群剔除；每段附来源批次与试听日期；你随时可查可删 |
| **重构引入回归**：拆 `run()` 时行为变了 | 难以定位的退化 | replay 等价性作为硬判据；重构与改行为分开提交 |
| **界面不被采纳**：你更习惯在资源管理器里听 | Phase 1.2 白做 | 提前让你试用 15 分钟；不喜欢就退回"手工 JSON + 我转写"，计划其余部分不受影响 |
| **过拟合 dev**：在 ep01–03 上反复调到很好 | 换集就崩（第三集已经教过一次） | LOEO 协议；test 集封存；每阶段最多 2 次迭代 |
| **参考音频本身不干净** | 上限被锁死，怎么调都不行 | Phase 0.4 一致性矩阵先行；发现问题先问你而不是自己换 |

## 附录 B：度量公式

**Wilson 95% 区间**（用于比例，小样本下比正态近似可靠）

对 p̂ = k/n，取 z = 1.96：

```
中心 = (p̂ + z²/2n) / (1 + z²/n)
半径 = z / (1 + z²/n) × sqrt( p̂(1-p̂)/n + z²/4n² )
区间 = 中心 ± 半径
```

**三倍法则**（0 错误时）

n 次观测中 0 次错误 → 95% 置信上界约 **3/n**。例：0/60 错误 → 上界 5.0%。

**分层召回估计**

对拒绝段分层 h = 1..H，每层抽 nₕ 段、被你判为目标的有 kₕ 段：

```
层内命中率 rₕ = kₕ / nₕ
整集漏检估计 = Σₕ  Nₕ × rₕ     （Nₕ 为该层拒绝段总数）
召回上界 = (已输出段数 + 整集漏检估计) / (已输出段数 + 实际目标总数)
```

置信区间用 bootstrap 重抽各层样本（固定随机种子，≥2000 次），报 2.5% 与 97.5% 分位。

**注意：** 这个估计只能给**下界意义**上的信息——你判为"目标"的被拒段至少说明有这么多漏掉了；真实召回可能更差，因为被拒段里也可能有你的目标被你听漏。
